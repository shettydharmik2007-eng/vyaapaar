## Part 1: Java & Object-Oriented Programming (OOP)

### Q1. What is Object-Oriented Programming (OOP) and how is it used in Vyaapaar?
**Answer:** OOP is a programming paradigm based on the concept of "objects" that contain data (fields) and code (methods). In Vyaapaar, OOP is used to model real-world entities (like `User`, `Product`, `Order`) into POJO classes, encapsulating their data and decoupling business operations.

### Q2. What is Encapsulation and where is it implemented in this project?
**Answer:** Encapsulation is the practice of keeping fields private and providing access through public getters and setters. It is implemented across all classes in the `com.vyaapaar.model` package.

### Q3. What is Separation of Concerns in software design?
**Answer:** It is a design principle where software is divided into distinct layers with independent responsibilities: UI handles user input/output, Services execute business rules, DAOs interact with the database, and Models represent data structures.

### Q4. How does Exception Handling work in Java and in this project?
**Answer:** Java uses `try-catch-finally` and `try-with-resources` blocks to intercept runtime errors. In Vyaapaar, SQL exceptions are caught inside DAOs, business validation errors throw `IllegalArgumentException` or `IllegalStateException`, and UI menus catch and format messages cleanly without crashing.

### Q5. What is the difference between `checked` and `unchecked` exceptions?
**Answer:** Checked exceptions (like `SQLException` and `IOException`) must be declared or caught at compile time. Unchecked exceptions (like `IllegalArgumentException` and `NullPointerException`) inherit from `RuntimeException` and are evaluated at runtime.

## Part 2: Java Database Connectivity (JDBC)

### Q6. What is JDBC and what role does it play in Vyaapaar?
**Answer:** JDBC (Java Database Connectivity) is a standard API that allows Java programs to execute SQL statements on relational databases. Vyaapaar uses JDBC drivers for MySQL and PostgreSQL.

### Q7. Why use `PreparedStatement` instead of `Statement`?
**Answer:** `PreparedStatement` pre-compiles SQL queries on the database server, improves execution performance for repeated calls, and protects against SQL Injection attacks by parameterizing values using `?` placeholders.

### Q8. What is a `ResultSet` in JDBC?
**Answer:** A `ResultSet` is a table of data representing a database result set generated by executing a `SELECT` query. It maintains a cursor pointing to its current row of data.

### Q9. What is `try-with-resources` and why is it used for database connections?
**Answer:** Introduced in Java 7, `try-with-resources` automatically closes any resource implementing `AutoCloseable` (like `Connection`, `PreparedStatement`, `ResultSet`) when the block exits, preventing database connection and memory leaks.

### Q10. What is `setAutoCommit(false)` in JDBC?
**Answer:** It turns off JDBC's default auto-commit mode, signaling the start of an explicit ACID transaction where multiple queries are executed and committed together.

## Part 3: Relational Database & SQL Concepts

### Q11. What is a Primary Key?
**Answer:** A Primary Key is a column or set of columns that uniquely identifies each row in a database table. In Vyaapaar, `user_id`, `product_id`, and `order_id` are primary keys.

### Q12. What is a Foreign Key and why is it important?
**Answer:** A Foreign Key is a field in one table that references the Primary Key of another table, establishing a relationship and enforcing referential integrity (e.g., `products.category_id` references `categories.category_id`).

### Q13. What is the difference between `INNER JOIN` and `LEFT JOIN`?
**Answer:** `INNER JOIN` returns only rows that have matching values in both tables. `LEFT JOIN` returns all rows from the left table and matched rows from the right table (filling with `NULL` if no match exists).

### Q14. What is the difference between `WHERE` and `HAVING` clauses?
**Answer:** `WHERE` filters individual rows *before* any grouping or aggregation takes place. `HAVING` filters aggregated groups *after* the `GROUP BY` clause has been applied.

### Q15. What are SQL Aggregate functions? Give examples.
**Answer:** Aggregate functions perform a calculation on a set of values and return a single summary value. Examples used in Vyaapaar include `SUM()`, `COUNT()`, `AVG()`, `MIN()`, and `MAX()`.

### Q16. What is a Subquery? Where did you use it?
**Answer:** A subquery is a query nested inside another SQL statement. In Vyaapaar, scalar subqueries are used in the executive sales summary and a `NOT IN` subquery is used to identify inactive customers.

### Q17. What is the `CASE` expression in SQL?
**Answer:** `CASE` allows conditional logic inside SQL queries (similar to `if-else`). In Vyaapaar, it is used in customer analysis queries to conditionally sum only non-cancelled orders.

### Q18. What is Database Normalization?
**Answer:** Normalization is the process of organizing data in a database to reduce data redundancy and improve data integrity. Vyaapaar tables are normalized up to 3rd Normal Form (3NF).

## Part 4: Vyaapaar Project Architecture & Workflows

### Q19. Why did you choose a 3-Tier Layered Architecture?
**Answer:** It decouples user interface logic from business calculations and database code. This makes the project maintainable, testable, and allows swapping or updating UI/database technologies without breaking core logic.

### Q20. Why are both MySQL and PostgreSQL used in this project?
**Answer:** MySQL is used as the primary OLTP database for day-to-day shopping and inventory operations. PostgreSQL is used as an OLAP/reporting database to showcase complex analytical SQL queries without overloading the transactional database.

### Q21. Explain the Data Access Object (DAO) Pattern.
**Answer:** The DAO pattern abstracts and encapsulates all access to the data source. It exposes clean methods (like `registerUser`, `addProduct`) that return Java objects, hiding low-level SQL syntax and JDBC connections.

### Q22. Explain the Service Layer Pattern.
**Answer:** The Service layer coordinates business workflows, enforces domain rules (e.g., stock check, password length, email format), and manages transaction boundaries before calling DAOs.

### Q23. How does the Checkout transaction work in Vyaapaar?
**Answer:** When the customer confirms checkout:
1. Active cart is retrieved and verified non-empty.
2. Available stock is verified for all items.
3. Total amount is calculated.
4. `conn.setAutoCommit(false)` begins the transaction.
5. Order header is inserted into `orders`.
6. Item price snapshots are batch-inserted into `order_items`.
7. Stock is deducted in `inventory`.
8. Active cart items are deleted.
9. `conn.commit()` finalizes the transaction.

### Q24. What happens if checkout fails midway (e.g., database disconnect or stock underflow)?
**Answer:** The `catch` block catches the exception and immediately invokes `conn.rollback()`. This discards all pending inserts and updates, ensuring zero orphaned orders, zero corrupted stock, and keeps the customer's cart intact.

### Q25. Why are unit prices copied into `order_items` instead of just referencing `products.price`?
**Answer:** If a product's price changes in the future, previous historical order totals must remain unchanged. Storing an immutable price snapshot in `order_items` preserves accurate financial history.

### Q26. How does Vyaapaar prevent negative inventory stock?
**Answer:** Through dual protection:
1. **Application level**: `InventoryService` validates `stock >= requestedQty` and rejects negative updates.
2. **Database level**: `inventory` table has a `CHECK (stock_quantity >= 0)` constraint.

### Q27. How does Vyaapaar prevent SQL Injection attacks?
**Answer:** By using `PreparedStatement` with parameterized `?` placeholders everywhere in the DAO layer, ensuring user inputs are treated as literal values rather than executable SQL commands.

### Q28. How are Customer and Admin roles separated in the system?
**Answer:** The `users` table contains a `role` column (`CUSTOMER` or `ADMIN`). When logging in, `AuthService` verifies the role and routes the user strictly to either `CustomerMenu` or `AdminMenu`. Customers are blocked from accessing administrative operations.

### Q29. What happens when an Admin adds a new product?
**Answer:** `ProductService` validates the category ID, saves the product in the `products` table via `ProductDao`, and automatically provisions a corresponding 1:1 stock record in the `inventory` table via `InventoryDao`.

### Q30. Why did you use Maven for this project?
**Answer:** Maven manages project lifecycle (compilation, packaging), standardizes folder layout (`src/main/java`, `src/main/resources`), and automatically downloads required external dependencies (`mysql-connector-j` and `postgresql` JDBC drivers).
